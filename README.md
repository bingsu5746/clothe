# 내 옷장 (clothe)

개인용 AI 옷장 & 코디 추천 웹앱(PWA). Cloudflare Workers 하나에 화면(React)과 API(Hono)가 같이 올라가고, D1(DB)과 R2(사진)를 씁니다. iPhone·iPad·Mac에서 Safari "홈 화면에 추가"로 앱처럼 씁니다.

## 기능

| 화면 | 기능 |
|---|---|
| 오늘 | 날씨·일교차 카드, 상황 키워드로 AI 코디 추천(퍼스널 컬러·체형 반영, 오래 안 입은 **장롱템**을 섞어 추천), 시밀러룩·커플룩(상대 옷 사진이나 설명 → 내 옷장 코디), 저장한 코디를 오늘 기온 순으로, "오늘 입을래요" 착용 기록 |
| 옷장 | 사진 → (선택) 기기 안에서 배경 제거 → Gemini 자동 태깅 / 쇼핑몰 링크로 가져오기 / 직접 입력. 착용 횟수·1회당 가격(CPW)과 **뽕 뽑기 게이지**(30번 입기 목표), 장롱템 표시 |
| 코디 | 저장한 코디 목록·직접 조합 / **OOTD 캘린더**: 거울 셀카를 올리면 AI가 옷장 옷과 맞춰 보고(확신도 표시), 확인하면 착용 횟수가 올라감. 달력에서 날짜별 셀카, 기록 고치기·지우기(착용 횟수 자동 조정) |
| 스크랩 | 인스타·핀터레스트 코디 사진 → AI가 옷을 나눠 내 옷장의 비슷한 옷과 매칭, 없는 옷은 위시리스트로 |
| 위시리스트 | 사고 싶은 옷과 총액, **살까 말까 판독**(0~100점: 중복·코디 시너지·퍼스널 컬러·체형 항목별 점수와 계산식), 구매 링크(네이버 쇼핑 검색 결과 또는 네이버·무신사·29CM 검색 링크, 직접 추가), "샀어요" → 옷장으로 |
| 여행 | 여행지·날짜·일정 메모 → 일기예보(출발 2주 이내)와 옷장으로 캡슐 옷장·날짜별 코디·여행 팁, 짐 체크리스트(체크·전체 체크·직접 추가·삭제, 다시 계획해도 체크 유지) |
| 프로필 | 키·몸무게, **퍼스널 컬러 진단**(얼굴 사진의 화이트밸런스를 기기에서 바로잡고 피부·머리·눈 색을 직접 찍어서 보냄 → 계절·세부 톤, 베스트/워스트 팔레트), **체형 진단**(전신 사진 → 스트레이트·웨이브·내추럴, 핏 가이드), 전신(마네킹) 사진 최대 6장 |
| 피팅룸 | **2D 콜라주 보드**(내 전신 사진이나 무지 배경 위에 옷 사진을 끌고·크기·순서·회전, 터치·마우스·키보드, 코디로 저장하면 그림이 코디의 대표 사진으로 같이 저장, 또는 기기에 저장) / **AI 가상 피팅**(선택·유료, 켜져 있을 때만) |
| 설정 | 테마, 날씨 위치, iPhone 단축어 연결 방법, 연결 상태(AI·가상 피팅·네이버 쇼핑·단축어 — `GET /status`) |

iPhone 공유 시트: iOS는 웹앱을 공유 목록에 직접 넣는 기능을 지원하지 않아서, 단축어 → `POST /api/webhook/shortcut`(헤더 `X-Shortcut-Token`)으로 사진·링크를 스크랩·위시리스트·옷장(`target=closet`)에 바로 저장해요. 설정 화면에 만드는 방법이 있어요.

## 배포

`main` 브랜치에 코드가 올라가면 Cloudflare가 빌드하고 배포합니다. 수정은 작업 브랜치 → PR → Merge 순서로 해요. 처음 한 번만 Cloudflare 대시보드에서:

1. Workers & Pages → `clothe` → Settings → Build → **Connect** → GitHub 저장소 선택, 브랜치 `main`
   - Build command: `npm run build`
   - Deploy command: `npx wrangler deploy`
2. Settings → Variables and Secrets 에 시크릿 추가

| 이름 | 필수 | 설명 |
|---|---|---|
| `APP_PIN` | 필수 | 로그인 PIN. 공개 주소라 6자리 이상 권장 (15분에 5번 틀리면 15분 잠김) |
| `GEMINI_API_KEY` | 필수(AI 기능) | [Google AI Studio](https://aistudio.google.com/apikey)에서 발급. 없으면 AI 기능마다 "키가 없어요" 안내가 떠요 |
| `SESSION_SECRET` | 권장 | 로그인 쿠키 서명 키, **16자 이상**. 없거나 짧으면 서버가 무작위 키를 만들어 D1에 저장해 써요 |
| `SHORTCUT_TOKEN` | 선택 | iPhone 단축어용 아무 긴 문자열. 없으면 단축어 저장이 항상 거절돼요 |
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 선택(무료) | 네이버 쇼핑 검색 API. 없으면 쇼핑몰 검색 링크만 보여 줘요 |
| `REPLICATE_API_TOKEN` | 선택(유료) | AI 가상 피팅(Replicate IDM-VTON). 없으면 피팅룸은 콜라주 보드만 |

변수(`wrangler.jsonc` 의 `vars`): `GEMINI_MODEL`(기본 `gemini-flash-latest`), `TRYON_PROVIDER`(`replicate` \| `gemini` \| 비움 — `gemini` 는 결제가 연결된 키 필요), `TRYON_MODEL`.

D1 데이터베이스(`clothe-db`)와 R2 버킷(`clothe-images`)은 첫 배포 때 wrangler가 자동으로 만들고, DB 테이블과 스키마 업그레이드는 앱이 첫 요청 때 알아서 적용해요(`wrangler d1 migrations apply` 는 쓰지 마세요).

> 이번 버전부터 쿠키 서명 키가 APP_PIN에서 분리되어, **배포 직후 한 번 모든 기기에서 다시 로그인**해야 해요(PIN 그대로). 로그아웃은 그 기기의 쿠키만 지우고 이미 발급된 다른 쿠키를 취소하지는 않아요. 모든 기기를 로그아웃시키려면 `SESSION_SECRET` 을 바꾸세요.

## 로컬 개발

```bash
cp .dev.vars.example .dev.vars   # 값 채우기
npm run dev
```

`npm test` 로 단위 테스트, `npm run typecheck` 로 타입 검사, `npm run lint` 로 린트.
`npm run e2e` 는 세 단계예요(Playwright 필요, 저장소 밖 임시 폴더에 격리된 상태만 써요).
1. `test/e2e/smoke.mjs`: 로컬 서버(포트 5184, PIN 1234, Gemini 키 없음)에 데이터를 넣고 390×844·820×1180(iPad)·1440×900을 라이트·다크로 모든 화면을 열어 봐요. 콘솔 오류·5xx·가로 넘침·h1 개수·이름 없는 컨트롤·axe-core(WCAG 2.1 AA) serious/critical 위반이면 실패. 키보드·포커스(시트/대화상자 포커스 가두기·Esc·되돌리기, 콜라주·달력·세그먼트·색 찍기), 배경 지운 사진의 IndexedDB 저장·복원, 동작 줄이기, AI 성공 경로(가짜 응답)도 눌러 봐요. `E2E_CONFIGS=m-light,t-dark` 로 화면 조합을 줄이고, `E2E_OUT=폴더` 로 스크린숏을 남길 수 있어요.
2. `test/e2e/upgrade.mjs`: `0001_init.sql` 만 적용한 진짜 로컬 D1(포트 5185)에 예전 데이터를 넣고 첫 요청을 동시에 보내 운영 DB 업그레이드(버전 1→2→3)와 데이터 보존, 착용·기록 수정·삭제, 사진 정리, 재시작 멱등성을 확인해요.
3. `test/e2e/journeys.mjs`: 빈 DB(포트 5186)에서 iPhone(390×844, 터치, 다크)으로 실제 사용 순서를 끝까지 눌러 보고 서버 값까지 확인해요 — 첫 로그인 → 사진·쇼핑몰 링크로 첫 옷, 오늘 추천 → 저장 → 입기(착용 횟수·CPW 게이지가 새로고침 없이 갱신), 단축어 웹훅(사진·링크·옷장), 스크랩 → 위시리스트 → 판독 → 링크 → 샀어요, OOTD → 달력 → 날짜 고치기 → 삭제(횟수 원래대로), 여행 계획·체크리스트(빠른 연속 체크, 다시 계획해도 유지), 키·몸무게 → 퍼스널 컬러(화이트밸런스·색 찍기) → 체형, 콜라주 → 코디, 테마 유지·로그아웃. 한글은 진짜 IME 조합 이벤트(Chrome DevTools Protocol)로 입력해요. AI 응답은 가짜(`page.route`)이고, 서버가 저장하는 AI 결과는 격리된 로컬 D1 파일에 직접 써서 흉내 내요. 가짜 쇼핑몰은 로컬 HTTP 서버라서 `/etc/hosts` 에 `127.0.0.1 shop.clothe-e2e.test` 가 필요해요(쓸 수 있으면 스크립트가 넣었다가 지우고, 못 쓰면 링크 단계만 건너뜀). `J=bdf` 처럼 여정을 골라 돌릴 수 있어요.

## 참고와 한계

- **AI 결과는 참고용이에요.** 퍼스널 컬러·체형 진단은 사진 한 장(조명, 화장, 자세)에 크게 좌우되고, 결과에 확신 정도와 주의할 점을 같이 보여 줘요. 화이트밸런스 보정은 그레이 월드(사진 평균) 또는 흰색 기준점 방식이라 완벽하지 않아요.
- **Gemini 무료 티어 한도**가 프로젝트마다 달라요. 같은 요청은 D1에 캐시해서 다시 호출하지 않고, 한도를 넘으면 429 안내가 떠요. 모델은 `GEMINI_MODEL` 로 바꿀 수 있어요.
- **AI 가상 피팅은 유료**(Replicate, 또는 결제된 Gemini 이미지 모델)라 기본으로 꺼져 있어요. Replicate는 상의·아우터·하의·원피스만 입힐 수 있고, 한 번에 30초~몇 분 걸려요.
- **콜라주 보드**: 배치와 "배경 지우기" 결과는 그 기기(브라우저 저장소·IndexedDB)에만 기억돼요(다른 기기에서는 원래 사진). "코디로 저장"하면 옷장 옷 목록과 보드 그림(코디 대표 사진)이 함께 저장돼요. 위시리스트 옷만 올린 보드는 그림을 기기에만 저장할 수 있어요. 쇼핑몰 주소로만 사진이 있는 위시리스트 옷은 그림으로 저장할 수 없어 보드에 올릴 수 없어요(AI 가상 피팅은 서버가 사진을 가져와서 쓸 수 있어요).
- **여행 예보**는 오늘부터 약 14일 안쪽 날짜만 있어요. 예보가 없는 날은 기온을 지어내지 않고 계절·메모 기준으로 계획해요.
- 날씨는 [Open-Meteo](https://open-meteo.com/) 무료 API(비상업용, 키 불필요)를 브라우저에서 직접 호출해요(실패하면 서버를 거쳐요).
- 사진은 업로드 전에 브라우저에서 최대 1280px로 줄여 WebP(지원 안 되면 JPEG/PNG)로 압축해요. 서버는 파일의 실제 형식을 확인하고, 링크 칸은 http(s) 주소만 받아요.
- 단일 사용자 앱이에요. 로그인은 PIN 하나뿐이니 PIN을 길게 쓰세요.
